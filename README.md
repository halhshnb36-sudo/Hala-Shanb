# موقع هالة شنب للعناية بالشعر

موقع عربي (RTL) بتصميم أسود وذهبي، مع لوحة إدارة محمية، وقاعدة بيانات Supabase، وتحليلات مشاهدات حقيقية، ونشر على Cloudflare.

> ## ⚠️ حالة الاختبار — اقرئي هذا أولًا
> كُتب هذا المشروع في بيئة لا تستطيع الوصول إلى سجل npm، لذلك **لم يُنفَّذ `npm install` ولم يُجرَ `npm run build` ولم يُجرَّب الموقع على Supabase أو Cloudflare فعليًا**.
> ما تم التحقق منه فعليًا: (1) ملف السيرة الكامل في SQL مطابق حرفًا بحرف للنص الأصلي (اختبار آلي)، (2) فحص أنواع TypeScript لكود المشروع مع استبدال المكتبات الخارجية بتعريفات فارغة (لم تظهر أخطاء في كودنا).
> **لم يتم التحقق من:** البناء الإنتاجي، تشغيل ملفات SQL على Supabase، سياسات الأمان عمليًا، رفع الفيديو المتقطّع (TUS)، النشر على Cloudflare.
> اتبعي «قائمة الاختبار» في `docs/TESTING.md` بعد التثبيت. وإن ظهر خطأ في أول بناء فهو على الأرجح خطأ بسيط في نسخ المكتبات أو الأنواع.
> **الشعار:** الشعار الأصلي المرفق موجود في `public/logo.png` ويظهر في الرأس والواجهة والتذييل، ويمكن استبداله من لوحة الإدارة.

## المكوّنات
| الجزء | التقنية |
|---|---|
| الواجهة | React 19 + TypeScript + Tailwind CSS 4 + Vite 7 |
| قاعدة البيانات والمصادقة والتخزين | Supabase (PostgreSQL + Auth + Storage + RLS) |
| الاستضافة | Cloudflare Workers (Static Assets + Worker صغير) |
| الرسوم البيانية | Recharts (تُحمَّل في لوحة الإدارة فقط) |
| رفع الفيديو الكبير | TUS (رفع متقطّع يمكن استئنافه) |

### لماذا Cloudflare Workers وليس Pages؟
- Cloudflare توجّه المشاريع الجديدة إلى **Workers مع Static Assets**، وهو يقدّم نفس إمكانات Pages تقريبًا.
- نحتاج Worker صغيرًا (`worker/index.ts`) لشيئين لا يوفّرهما وضع SPA البسيط: توجيه الروابط المباشرة مثل `/biography` و`/admin` إلى التطبيق، **وإرجاع حالة HTTP 404 حقيقية** للصفحات غير الموجودة (مفيد لمحركات البحث).
- لا توجد أي أسرار في Cloudflare: المتصفح يتصل بـ Supabase بالمفتاح العام (publishable)، والحماية كلها في قاعدة البيانات (RLS). **مفتاح `service_role` لا يُستخدم في أي مكان.**

## 1) التثبيت المحلي
المطلوب: Node.js 20 أو أحدث (يفضّل 22).

```bash
npm install
cp .env.example .env.local       # ثم عدّلي القيم (الخطوة 2)
npm run dev                      # http://localhost:5173
npm run build                    # فحص الأنواع + بناء الإنتاج إلى dist/
```

## 2) إعداد Supabase

1. أنشئي مشروعًا على https://supabase.com.
2. من **Project Settings → API Keys** انسخي: **Project URL** و **Publishable key** (يبدأ بـ `sb_publishable_`؛ أو مفتاح `anon` القديم). ضعيهما في `.env.local`:
   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
   VITE_SITE_URL=https://your-domain.example
   ```
3. **طبّقي ملفات قاعدة البيانات بالترتيب** (اختاري طريقة واحدة):

   **أ) من لوحة Supabase (الأسهل):** SQL Editor → الصقي وشغّلي كل ملف من `supabase/migrations/` بالترتيب:
   `001_schema.sql` ثم `002_rls_policies.sql` ثم `003_storage.sql` ثم `004_analytics.sql` ثم `005_seed_settings.sql` ثم `006_seed_biography.sql`.

   **ب) عبر Supabase CLI:**
   ```bash
   npx supabase init                       # ينشئ config.toml فقط
   npx supabase login
   npx supabase link --project-ref YOUR-PROJECT-REF
   npx supabase db push                    # يطبّق كل ملفات supabase/migrations
   ```

   ما تفعله الملفات: الجداول (`profiles`, `site_settings`, `articles`, `media`, `content_views`)، تفعيل RLS وسياساته، إنشاء حاويات التخزين (`branding`, `articles`, `gallery`, `videos`) وسياساتها، دوال التحليلات، الإعدادات الأولية، والسيرة الكاملة كأول مقال منشور.
4. **عطّلي التسجيل العام:** Authentication → Providers (أو Sign In / Providers) → Email → أوقفي **Allow new users to sign up**. (حتى لو بقي مفعّلًا، أي حساب جديد لا يملك أي صلاحية إدارة لأنه غير موجود في جدول `profiles`.)
5. **Authentication → URL Configuration:** ضعي `Site URL` = عنوان موقعك النهائي.
6. **حجم الفيديو:** حاوية `videos` مضبوطة على 500 م.ب، لكن الخطة المجانية في Supabase تحدّ كل ملف بـ 50 م.ب على مستوى المشروع. لرفع ملفات أكبر: ارفعي حد الملف من **Storage → Settings** (خطة مدفوعة)، أو استخدمي روابط يوتيوب/فيميو (مدعومة في لوحة الإدارة).

## 3) إنشاء أول مدير (بشكل آمن)
المدير = حساب في Supabase Auth **و** له صف في `public.profiles`. لا توجد كلمة مرور في الكود ولا صفحة تسجيل عامة.

1. Supabase → **Authentication → Users → Add user → Create new user**: أدخلي البريد وكلمة مرور قوية، وفعّلي **Auto Confirm User**.
2. في **SQL Editor** شغّلي (بعد استبدال البريد):
   ```sql
   insert into public.profiles (id, role)
   select id, 'admin' from auth.users where email = 'YOUR-EMAIL@example.com'
   on conflict (id) do nothing;
   ```
3. افتحي `/admin` وسجّلي الدخول.

لإضافة مدير آخر كرّري الخطوتين. لإلغاء صلاحية مدير: `delete from public.profiles where id = '...';`

## 4) النشر على Cloudflare

يتطلب حساب Cloudflare مجانيًا. **لا تعتبري الموقع منشورًا قبل أن يعمل الرابط فعليًا.**

### الطريقة أ: ربط GitHub (مفضّلة — نشر تلقائي)
1. ارفعي المشروع إلى مستودع GitHub (الملف `.gitignore` يمنع رفع الأسرار).
2. Cloudflare Dashboard → **Workers & Pages → Create → Import a repository**.
3. إعدادات البناء:
   - **Build command:** `npm run build`
   - **Deploy command:** `npx wrangler deploy`
4. أضيفي **Build variables** (Settings → Build → Variables and secrets): `VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY` و`VITE_SITE_URL`. هذه قيم عامة وليست أسرارًا، لكنها تُدمج وقت البناء، فأي تغيير فيها يتطلب إعادة بناء.
5. اضغطي Deploy. سيظهر الموقع على عنوان `https://hala-shanb.<account>.workers.dev` مع HTTPS تلقائي.

### الطريقة ب: من جهازك
```bash
npx wrangler login
npm run deploy        # يبني ثم ينشر
```
(ضعي متغيرات `VITE_*` في `.env.local` قبل البناء.)

### دومين مخصّص لاحقًا
Workers & Pages → مشروع `hala-shanb` → **Settings → Domains & Routes → Add → Custom domain** → أدخلي الدومين (يجب أن تكون منطقة الدومين على Cloudflare DNS). شهادة HTTPS تُنشأ تلقائيًا. بعدها حدّثي `VITE_SITE_URL` وSupabase `Site URL` وأعيدي النشر.

### التوجيه وصفحة 404
- الملفات الحقيقية (JS/CSS/صور) تُخدم مباشرة.
- `/biography` و`/articles/...` و`/admin/...` تُرجع التطبيق بحالة 200.
- أي مسار غير معروف يُرجع صفحة 404 الخاصة بالتطبيق بحالة HTTP 404.
- ترويسات الأمان (CSP وغيرها) في `public/_headers`. إن استخدمتِ دومين Supabase مخصّصًا أضيفيه إلى `img-src`/`media-src`/`connect-src`.

## 5) نظام الأمان باختصار
- **RLS مفعّل على كل الجداول.** الزائر (anon) يقرأ فقط: المقالات المنشورة (وتاريخ نشرها وصل)، الوسائط المنشورة، والإعدادات.
- الإدارة (CRUD، الرفع، الحذف) مقصورة على من لهم صف في `profiles` عبر الدالة `is_admin()` — داخل قاعدة البيانات، وليس بإخفاء الأزرار.
- جدول `content_views`: **لا كتابة مباشرة** من المتصفح. التسجيل فقط عبر `track_view()` التي تتحقق أن المحتوى منشور، وتمنع التكرار، وتحدّ المعدّل. إحصائيات الإدارة عبر دوال تفحص `is_admin()`.
- ملفات الفيديو في حاوية **خاصة**؛ الزائر يحصل على رابط مؤقت فقط للفيديوهات المنشورة. أما الصور والأغلفة فحاويات عامة بأسماء عشوائية غير قابلة للتخمين (تنبيه: من عرف رابط صورة غير منشورة يستطيع فتحها).
- نصوص المقالات تُعرض كنص عادي (لا HTML)، فلا ثغرات XSS من المحتوى المخزَّن.
- أنواع الملفات وأحجامها محدّدة في الواجهة وفي حاويات Supabase (بلا SVG).
- الأسرار: لا يوجد أي سر في المشروع. `.env.example` يحوي قيمًا شكلية فقط.

## 6) ماذا تقيس الأرقام؟
| المقياس | يُحتسب عندما | حد التكرار (نفس الجلسة) |
|---|---|---|
| مشاهدة مقال / السيرة (`page_view`) | تُفتح الصفحة | 30 دقيقة |
| مشاهدة صورة (`image_view`) | تُفتح الصورة في العرض المكبّر أو يُنتقل إليها | 10 دقائق |
| تشغيل فيديو (`video_play`) | يبدأ التشغيل (يوتيوب/فيميو: عند فتح المشغّل) | 5 دقائق |
| إجمالي زيارات المحتوى | مجموع كل الأحداث، وليس عدد الأشخاص | — |

لا يُخزَّن IP ولا بيانات شخصية؛ فقط معرّف جلسة عشوائي مؤقت. زياراتك كمديرة مسجّلة الدخول لا تُحتسب. الأيام بتوقيت القاهرة.

## 7) استخدام اللوحة
`/admin` ← الإحصائيات، المقالات، السيرة الذاتية، الصور، الفيديو، إعدادات الموقع (الشعار، الهاتف، العنوان، روابط التواصل، ترتيب أقسام الصفحة الرئيسية، بطاقات الخدمات، SEO، اللون).
- **الصورة/الفيديو المميّز في الصفحة الرئيسية:** زر «تمييز» على أي صورة أو فيديو منشور (عنصر واحد في كل مرة).
- **أيقونات التواصل:** كلها مُعطّلة في البداية. أضيفي الرابط الحقيقي ثم فعّلي الأيقونة. واتساب يبني رابط المحادثة من الرقم تلقائيًا.
- **نص المقالات:** افصلي الفقرات بسطر فارغ؛ `## ` عنوان، `### ` عنوان صغير، `> ` اقتباس.
- التعديلات غير المحفوظة تُنسخ احتياطيًا في المتصفح وتُعرض للاستعادة إن انقطع الاتصال أو أُغلقت الصفحة.

## 8) قيود معروفة (بصراحة)
- **معاينة روابط المشاركة:** الموقع تطبيق صفحة واحدة؛ محركات البحث مثل Google تقرأ العناوين المحدّثة، لكن معاينات فيسبوك/واتساب لا تشغّل JavaScript فتعرض بيانات الموقع العامة وليس بيانات كل مقال. الحل لاحقًا: توليد وسوم Open Graph من الـ Worker.
- **روابط يوتيوب/فيميو:** لا يمكن معرفة لحظة التشغيل الفعلي داخل مشغّل خارجي، فتُحتسب مشاهدة عند فتح المشغّل.
- **الحماية من التلاعب بالعدّادات** تقلّل المحاولات (تحقق + تكرار + حدود معدّل) لكن من يولّد جلسات كثيرة عمدًا قد يزيّف أرقامًا قليلة. للحماية الأقوى مرّري التتبع عبر Worker مع Rate Limiting.
- **ترتيب الصور/الفيديو** بأزرار تقديم/تأخير (وليس سحبًا وإفلاتًا)، وتتعطّل أثناء البحث/التصفية.
- لا تُحذف الملفات اليتيمة تلقائيًا إن أُغلقت الصفحة بعد رفع ملف دون حفظ (بقاؤها لا يضرّ ويمكن حذفها من Supabase Storage).
- الصور تُصغَّر في المتصفح (حتى 2400px) قبل الرفع؛ لا يوجد تحويل صور من جهة الخادم (يتطلب خطة مدفوعة).

## 9) بنية المشروع
```
supabase/migrations/   ملفات SQL (الجداول، RLS، التخزين، التحليلات، البيانات الأولية)
supabase/seed/         نص السيرة الأصلي
scripts/               مولّد ملف السيرة (build_biography_seed.py)
worker/index.ts        Worker: التوجيه + 404 حقيقي
wrangler.jsonc         إعداد Cloudflare
public/                الشعار، _headers، robots.txt
src/lib/               supabase، الإعدادات، التتبع، الرفع، أدوات
src/components/        الرأس، التذييل، البطاقات، العارض، المشغّل…
src/pages/             الصفحات العامة
src/admin/             لوحة الإدارة (تُحمَّل كحزمة منفصلة)
docs/TESTING.md        قائمة الاختبار
```

لإعادة توليد ملف السيرة من النص الأصلي: `python3 scripts/build_biography_seed.py` (ينفّذ فحصًا آليًا أن النص لم يتغيّر).
